## 1. 本轮已改（可验证）

### 1.1 会话失效不再让用户点“重试”死循环

**现象（真机复现）**：用同一账号在另一台设备/原版 App 登录后，小谷云首页只显示

```
加载失败：账号已在其他设备登录
[                重试                ]
```

点“重试”必定再失败一次，没有任何出路；用户只能杀进程。

**原因**：`DeviceListActivity.loadDevices()` 的 catch 只对 `ApiException.code == 401`
做清 token + 回登录页，服务端“同账号他处登录”走的是另一套 code/message，落进了普通失败分支。

**改法**（`ui/DeviceListActivity.kt`）：

- 新增 `isSessionInvalid(e, msg)`：401 或 message 命中「其他设备 / 重新登录 / 登录已过期 /
  登录失效 / 未登录 / token / 账号异常」即判定会话失效；
- 命中后：`store.clear()` → Toast 说明原因 → 跳 `LoginActivity` 并 `finish()`，
  登录页会自动带出记住的账号密码（`TokenStore.saveCredentials` 不受影响，体验是“一键重登”）；
- 普通网络错误仍保留原“重试”按钮，行为不变。

> 真机状态：改动已编译、已用团队证书（`CN=Android Debug`，SHA-256 `6f4115…a658b0`）覆盖安装并跑通登录/设备列表。
> 该分支路径本身未在真机触发（本次重新登录成功，反而把原版大谷云的会话挤下线了）。

## 2. 大谷云 v9.0 的能力清单（解包所得，作为移植对照表）

原版 `com.dgiot.speedmonitoring` v9.0 共 65 个自有 Activity（去广告后清单已清空广告组件），
按功能归类如下（★ = 小谷云当前没有或明显更弱）：

| 类别 | 原版能力 | 小谷云现状 |
|---|---|---|
| 配网/绑定 | ★ 扫码添加、★ WiFi 直连添加、★ 蓝牙添加、绑定结果页、绑定失败处理、设备选择列表 | 无（只能看已绑定设备） |
| 设备管理 | 设备列表、设备详情、基础信息、固件信息、★ 固件升级、★ 灵敏度、★ 报警设置、★ 录像设置/录像时间段、★ TF 卡信息与格式化、分享授权控制 | 有列表/详情/回放/SD 卡，设置类不全 |
| 直播 | 多画面、清晰度、云台、对讲、抓拍、录像、补光灯、追踪、★ 画面翻转、★ 夜视/宽动态等图像项 | 基本齐（1.2.4 补光灯、1.2.8 预置点） |
| 回放 | 云端录像列表、SD 卡录像列表 | 有 |
| 消息 | 报警/侦测事件列表、★ 消息按日期筛选与已读态 | 有基础列表 |
| 分享 | ★ 分享给家人、★ 分享账号权限、分享二维码 | 无 |
| 商业 | 订单列表、支付页、云存套餐、客服 Web、活动页 | 无（也不建议移植） |
| 账号 | 登录/注册/找回、账户设置、一键登录 | 有登录/找回 |

**建议移植顺序（按用户价值/风险比）**
1. **分享**（分享设备给家人 + 权限控制）：原版有完整的 `ShareDeviceBindActivity` /
   `ShareDeviceAuthControlActivity` / `ShareAccountActivity`，协议侧是 REST，不涉及 WS 命令码，
   风险最低、收益直接。
2. **报警/侦测设置**（开关、灵敏度、时间段）：原版 `DeviceAlarmSettingActivity`
   + `DeviceSensitivityActivity`；对应 WS code 14/15（侦测开关/查询）已在交接文档中有记录。
3. **TF 卡格式化**（已在 SD 卡页？需核对是否含格式化入口与二次确认）。
4. **固件升级 OTA**：原版有 `DeviceFirmwareInfo(New)Activity`，走 REST 下载 + 本地安装，
   涉及安装权限，做之前要先确认是否需要。
5. 配网三件套（扫码/WiFi/蓝牙）：价值高但工作量最大，且要真机反复试，放最后。

## 3. 小谷云的交互问题（真机观察，按影响排序）

1. **会话失效无出路**（已修，见 1.1）。
2. **登录页底部有一段“开发者说明”横幅**：`说明：勾选“记住账号密码”后……短信验证在原 App 中只用于注册/找回，
   不会直接登录……`。这是写给维护者看的，占掉近半屏，用户第一眼看到的是免责声明而不是登录。
   → 建议删掉或折进“关于/帮助”，登录页只保留一句「登录你自己的大谷云账号，无广告」。
3. **登录页两个单选（密码登录/短信登录）命中区太小**（RadioButton 本体约 20dp），
   横向紧贴输入框；建议改成两个 tab 文本按钮，整段可点。
4. **“忘记密码”整条宽白底按钮与主按钮“密码登录”视觉竞争**：主操作应该是唯一的实心按钮，
   忘记密码应是文字链接，放输入框右侧或按钮下方居中。
5. **首页设备卡信息层级混乱**：缩略图左上角叠着 `2026-11-25 21:54:49` 时间戳、左下角叠通道名
   （通道1·全景相机 / 通道2·特写相机 / 通道3·双画面），三个通道图尺寸还不一致；
   `电量 0%` 与右上角「在线」并列，用户无法判断是没电还是没取到。
   → 建议：时间戳弱化（右下角 10sp 半透明）或不显示；通道名做成等宽标签条；电量取不到时显示 `电量 —`。
6. **功能入口分裂**：底部导航有「功能」页（工具宫格），直播页里又有一整套功能区
   （画面与声音/抓拍与录像/云台控制/语音对讲）。同一件事两个入口，用户不知道哪个是“完整版”。
   → 建议明确分工：直播页只放“当前画面相关”的即时操作，功能页放“设备级设置与记录”，
   并在功能页每项后面加一句“在直播页也可操作”。
7. **失败态只有一条通栏蓝色“重试”**：无网络时这块占满主视觉，且不说明是网络问题还是账号问题。
   → 建议区分「网络不可用 / 服务器错误 / 会话失效」三种文案与动作。

## 4. 工程备注

- 本地构建：`gradle.bat assembleDebug`（Gradle 8.2 + JDK17 + SDK android-34），
  `local.properties` 里 `sdk.dir` 与 `signingKeystore` 指向团队 keystore，
  产物与线上 debug 包同证书，可覆盖安装平板现有版本。
- `local.properties`、`*.apk`、`build/` 均在 `.gitignore` 内，凭证不入库。
- 本分支只做小步改动，不碰 `main`；发版仍由用户/muse 决定。
